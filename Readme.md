# 7주차 사용자 흐름(Task Flow) 프로젝트

## 1. 서비스 정보 및 목적
- 서비스명: 신선한 냉장고
- 주요 사용자: 식재료 유통기한을 놓치기 쉬운 1인가구 및 자취생
- 서비스 목적: 냉장고 속 식재료 유통기한을 한눈에 파악하고 알림을 등록하여 음식을 버리는 일을 방지합니다.

## 2. 완료할 핵심 행동 및 조건
- 핵심 행동: 식재료 정보 입력 ➔ 보관 방식 및 유통기한 설정 ➔ 최종 확인 ➔ 등록 완료
- 완료 조건: 식재료명, 카테고리, 보관장소, 유통기한의 필수값이 모두 올바르게 입력되어야 최종 완료 단계에 도달함.

## 3. 사용자 흐름 (Task Flow) 시나리오
1. 1단계 (기본 정보): 식재료 이름과 카테고리를 선택합니다. 필수값 미입력 시 에러 문구가 출력되고 진행이 차단됩니다.
2. 2단계 (보관 및 기한): 보관 장소와 유통기한 날짜를 지정합니다.
3. 3단계 (최종 확인): 이전 단계에서 입력한 데이터가 요약 상자에 자동 반영됩니다. 이전 버튼 클릭 시 입력한 값이 그대로 유지된 채 수정할 수 있습니다.
4. 4단계 (등록 완료): 완료 메시지가 표시되며, '다른 식재료 추가 등록하기' 클릭 시 모든 입력값과 상태가 초기화되어 1단계로 되돌아갑니다.

## 4. 인터랙션 구조
- `행동`: 다음 버튼 클릭 ➔ `이벤트`: click ➔ `조건`: 필수값 validation ➔ `화면 반응`: 에러 메시지 노출 또는 다음 패널 보이기 ➔ `다음 상태`: 해당 Step 활성화

## 5. 반응형 테스트 결과
- 1100px / 768px / 390px 화면에서 스텝 프로그레스 바와 버튼 배치가 세로로 자동 정렬되어 가로 스크롤 없이 정상 조작됨을 확인했습니다.

# 중간고사 프로토타입 구현 보고서

## 1. 7주차 결과물 대비 새로 추가된 기능
7주차 '4단계 식재료 등록 흐름' 완료 시 입력된 데이터를 실시간 배열(`foodList`)에 동적으로 누적하고, 하단의 '실시간 나의 냉장고 현황판'에서 D-Day 계산, 검색/보관장소/상태 탭 필터링, 소비 완료 토글 피드백 및 예외 빈 상태(Empty State) 안내를 조작할 수 있는 관리 사용 경로를 구현했습니다.

## 2. 사용자 행동, 조건, 피드백 시나리오
- 사용자 행동 1 (검색/필터링): 검색창 입력(`input`), 보관장소 선택(`change`), 상태 탭 클릭(`click`)
  - 조건: 입력한 검색어 및 선택 조건에 맞는 식재료 검색
  - 성공 반응: 조건에 해당하는 식재료 카드만 화면에 필터링되어 즉시 노출
  - 결과 없음(예외) 피드백: '조건에 맞는 식재료가 없습니다' 문구 출력 ➔ `[필터 초기화]` 및 `[새 식재료 등록하기]` 버튼 제공

- 사용자 행동 2 (소비 완료 토글): 식재료 카드의 `[소비 완료 처리]` 버튼 클릭(`click`)
  - 조건: 해당 식재료의 상태가 `storing`인 경우
  - 성공 반응: 식재료 제목 취소선 처리, 딤 스타일 적용, D-Day 태그가 '소비 완료'로 변경되며 상단 통계 바(보관 중/소비 완료 개수)가 실시간 업데이트됨. 다시 클릭 시 '보관 중' 상태로 복원됨.

## 3. 테스트 및 검증 결과
- 정상 경로: 7주차 4단계 폼에서 식재료 등록 완료 시, 대시보드 상단 통계 수치가 증가하고 새 식재료 카드가 맨 앞에 즉시 생성됨을 확인했습니다.
- 오류 및 예외 경로: 존재하지 않는 식재료명(예: "치킨") 검색 시 `emptyState` 박스가 노출되며, `[필터 초기화]` 클릭 시 모든 필터 조건과 화면 목록이 정상적으로 원상 복구됩니다.
- 반응형 화면 (1100px, 768px, 390px): 개발자 도구 기기 모드에서 통계 바와 검색/필터 영역, 카드가 세로 1열로 유동 배치되어 가로 스크롤 없이 정상 작동함을 확인했습니다.
